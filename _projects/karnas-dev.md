  - title: "Moving files between panes"
    content: "Tabs can be reordered by dragging, and files can be dragged from the explorer into the editor. Dropping a file at the right edge opens a second pane, so visitors can keep a project beside the skills page or compare two pieces of work. Tabs can also move between panes, with a draggable divider controlling the space each side receives."
    second_content: "The interaction spans the explorer, tab bars, and split-view state. Each drop needs to preserve tab order, select the right file, and update the source pane consistently. The right pane renders a shared page inside an iframe, with its own scrolling and navigation coordinated with the parent workspace. The split layout and open files are restored after a refresh."
  - title: "A terminal that belongs to the workspace"
    content: "The terminal offers another way to explore the portfolio. It is a browser-based simulation with a virtual filesystem built from the same navigation data as the explorer. Visitors can browse directories, open pages, and read project or blog content through commands."
    list:
      - "ls and tree list the available files; cd changes the working directory, while open navigates without changing it."
      - "cat reads content loaded through the site's content API, and find searches the available entries."
      - "Command history, path completion, and keyboard shortcuts support a familiar terminal workflow."
      - "theme and particles share the appearance settings used by the rest of the workspace; matrix adds a canvas effect with reduced-motion support."
    second_content: "The implementation separates command handling, path resolution, and output rendering. Directory state stays independent of the current page, file listings render as accessible controls, and the split pane can open the same terminal through validated same-origin messages. Those details make it a working part of the editor interface."
    image: "/assets/projects/karnas-dev/terminal-composite.webp"
  - title: "Working at different widths"
    content: "The application needs to work on a phone and inside a narrow split pane on a large screen. Container-based layouts adapt the content to its actual available space. Navigation, scrolling, image sizing, and controls need to stay usable as the workspace changes."
    image: "/assets/projects/karnas-dev/mobile-composite.webp"
  - title: "From design to maintenance"
    content: "I used Figma to explore key elements and Jira to organize the initial work. The implementation uses TypeScript, React, Sass modules, and a small server-side content layer. It is deployed on Vercel and continues to evolve through visual review, browser checks, and targeted tests for preferences, folder state, and gallery behavior. Appearance settings let visitors personalize the workspace, with preferences preserved between visits."
    image: "/assets/projects/karnas-dev/settings.webp"
